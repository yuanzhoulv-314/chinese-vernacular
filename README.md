# chinese-vernacular

一个中文写作 skill：让 AI 以真正的人类视角写作，写完之后再检测并去除 AI 痕迹，最后直接交付成品

## 现有去AI味工具有什么缺点？

现有的中文去 AI 味工具，大多是在成稿上做文章，检测或者消除AI特征

- 只治标：它们改的是字面，管不到更早的地方：论证发散、段落等长、句长均匀、结构千篇一律。这些毛病是写的时候就带进去的，事后替换救不回来。
- 按词表硬删：看到**不是而是**，**值得注意的是**就删，但这类句型真人也在用，删完后要么句子空了，要么把有效的对比也一起删了
- 自己审自己：同一个模型写、同一个模型审，由于上下文污染大概率原样留着各类痕迹；把黑名单塞进写作提示词，行文还会被带成对表填空。
- 管不住别的格式：文档、幻灯片里的排版，一换格式就乱。

## 它怎么做

写作和审查分成两段，各管各的。

1. 拆分单元：成品由几块能独立成文的部分组成时分块处理。
2. 构思：写清写作主题、论据清单、事实黑名单、文风，判定语体与结构档位。
3. 提纲：排段落序列，大致定段落长短。
4. 逐段写作：段前有构思，写作有细节，段后有审查。
5. 使用子代理进行公式化审查，避免风格渗透导致的一系列问题。
6. 终审与汇总：断句、重复、结构、符号、标点五项过一遍，再合并交付。

## 我们的优势

- 先写对，再清洗，不靠事后打补丁。
- 主笔和审查者分开。写的人只管内容，机械检查交给另一双眼睛，避免上下文污染（同一个上下文中，AI难以看出自己的AI味）
- 匹配检测部分只报不改：检测结果带判断条件，改不改由模型按语境定，误杀少。
- 全程落文件：每一步都有产物，可追溯，断了能接上。
- 中文专属：单双音节、语体、标点、符号，处理的都是中文语境里的问题。

## 过程文件

所有中间文件会被放在成品同目录的 `<成品名>_work/` 里：

| 文件 | 用途 |
| --- | --- |
| `构思与提纲.md` | 所有单元按节记录构思与提纲 |
| `01-单元名.md` | 单元正文，编号即拼接顺序，全程不动 |
| `01-单元名_review.md` | 脚本生成的点评稿，正文里穿插点评块 |
| `01-单元名_edit.md` | 原稿的干净副本，子代理在这里改，改完即成品单元 |

## 安装

把整个目录放进所用 agent 的 skills 目录，例如：

```
~/.claude/skills/chinese-vernacular/
```

## 使用

让 agent 在工作时使用该技能即可。一个典型请求：

```
用技能 chinese-vernacular 帮我写一篇关于远程办公的评论，两千字左右。
```

流程会自己在成品目录建 `_work/` 文件夹，逐单元推进，最后按用户要求的格式合并

## 使用效果

详见`~\example`：`prompt.txt`为使用的提示词，`without_that_skill`为不使用该技能时的产物，`with_the_help_of_chi-ver`为使用该技能时的产物。
